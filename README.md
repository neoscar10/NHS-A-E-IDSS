# NHS A&E IDSS — M01 Inventory and M02 Ingestion

**Project:** [NHS-A-E-IDSS](https://github.com/neoscar10/NHS-A-E-IDSS)  
**Dataset:** Public NHS England monthly A&E attendances and emergency admissions CSV extracts, January 2022–September 2026.  
**Source snapshot checked:** GitHub `main` tree `5eaf2334350a4ffb7f1b5b660af4ac3c2ad50f31` (16 November 2026).  
**Scope:** Ingestion only. Source data are not cleaned, filtered, imputed, or used for forecasting during these milestones.

## 1. Where to put these files

Copy `src/data/m01_m02.py` and `tests/test_m01_m02.py` into the corresponding folders of your existing repository; do not replace the `data/raw/` files. `notebooks/01_m01_m02_inventory_ingestion.ipynb` can be opened separately in Google Colab and is also self-contained. This ZIP is a handover package; it does not change the GitHub repository.

## 2. Run locally after cloning

```bash
git clone https://github.com/neoscar10/NHS-A-E-IDSS.git
cd NHS-A-E-IDSS
# Copy this handover package's src/data and tests files into the repo, then:
python -m pip install pandas pyarrow pytest
python src/data/m01_m02.py --repo . --start 2022-01 --end 2026-09
python -m pytest -q tests/test_m01_m02.py
```

If the GitHub dataset changes, adjust `--end` to the latest month or investigate missing/duplicated months. The script records source hashes before ingestion, and stops M02 if M01 finds a schema, period, or coverage issue.

## 3. Run in Colab

Open [Google Colab](https://colab.research.google.com/) → **Upload notebook** → `01_m01_m02_inventory_ingestion.ipynb` → **Runtime > Run all**. The notebook clones the public repo if it is not already available in `/content`, then performs both phases and shows the outputs. Download your results from the Colab Files panel; runtime storage is temporary.

## 4. Outputs

| File | Phase | Interpretation |
|---|---|---|
| `docs/source_manifest.csv` | M01 | Every source CSV: filename, year/month, SHA256, row count, schema and preliminary alerts |
| `docs/m01_coverage.json` | M01 | Expected months, missing/duplicate months, row counts |
| `data/staging/ae_historical_raw_combined.csv` | M02 | Combined source values and four additional provenance fields |
| `data/staging/ae_historical_raw_combined.parquet` | M02 | Same dataset in a typed, compact container (when pyarrow is installed) |
| `data/staging/m02_ingestion_summary.json` | M02 | Combined row and file counts |

**IMPORTANT:** These are staging files, *not* a cleaned research dataset. National `TOTAL` rows, structural zeros, exact original source column names and string representations of counts are deliberately retained. The four added metadata fields are `source_month`, `source_file`, `source_sha256`, and `source_record_number`. Raw files remain unchanged in `data/raw/`.

## 5. What is deferred to M03–M05?

Count reconciliation across all 18 numeric fields; duplicate provider/month keys; missing provider reporting months; Type 1 structural zeros versus true non-reporting; organisation renames and mergers; outlier investigation; harmonised numeric types and modeling-specific exclusions. The preliminary M01 checks do **not** certify any of these.

## 6. Reproducibility and test coverage

`tests/test_m01_m02.py` runs using explicitly **synthetic fixture records**. It verifies file integrity, date parsing, `TOTAL` variants, strict month coverage, schema warnings, and source hash changes. Passing those tests establishes code behaviour on fixtures, **not** that every real NHS CSV has passed production checks. Re-run against your clone and keep the emitted manifest and summary with the project.

Data source information: [NHS England A&E activity releases](https://www.england.nhs.uk/statistics/statistical-work-areas/ae-waiting-times-and-activity/).

## 7. Verified GitHub listing provided separately

`docs/github_source_index_snapshot.csv` records the **57 filenames and published GitHub file sizes** visible on the inspected `main` tree (12 files each for 2022–2025; 9 for 2026). It is a remote directory inventory, **not** the full M01 `source_manifest.csv`: it has no calculated local SHA256 hash, CSV row count, or data-quality result. Those are generated by executing the pipeline against downloaded source bytes.

For a cleaner repository, consider adding `data/staging/` to `.gitignore` if you do not wish to commit the combined raw staging extracts; you can still commit the small source manifest and data-quality documentation.
